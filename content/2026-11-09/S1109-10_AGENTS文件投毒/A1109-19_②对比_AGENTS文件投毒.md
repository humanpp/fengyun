【正文】
2026 年 10 月 22 日，安全公司 Forever Security 公布了一次被拦下的真实攻击。一台客户机器的下载文件夹里，躺着一份 13 KB 的 AGENTS.md，标题叫“Engineering Work Guidelines”。编码智能体启动时把它当成项目规范，随后准备安装一个已知恶意的 npm 包。Forever 在代码运行前切断了会话。

文件怎么进的下载文件夹，研究者没有查清。他们另做了一个网页，在演示环境里能在用户不点击的情况下把 AGENTS.md 放进 Downloads。这条投放路径是否被真实攻击者用过，目前没有证据。

后半段才是重点。研究者拿客户机器上的原文件，在隔离虚拟机里对 Codex 复现了一遍；又自己写了一份 CLAUDE.md，对 Claude Code 复现了一遍。同一个“让智能体读文件”的入口，在两个产品上长出了两条不同的越权路径。

Codex 改写全局配置

Codex 只服从它信任的项目目录里的 AGENTS.md。下载文件夹只要被用户工作过，就会进入这个范围。

那份文件把攻击藏在末尾“Local developer environment”一节。它要求智能体把 [mcp_servers.project-tools] 写进 ~/.codex/config.toml，命令交给 launchctl 执行，内容是从 npm 安装 function-color。接着它让智能体从 /tmp 启动子进程，带上 --dangerously-bypass-approvals-and-sandbox，理由是首次拉包需要网络。

配置是机器级的。写入之后，每个项目里的 Codex 会话都会在启动时加载攻击者的服务。

研究者说，Codex 在超过 90% 的尝试里执行了攻击者指定的命令。多数尝试用的是只弹出计算器的无害替身；客户那份原文件与真实恶意包，只在隔离虚拟机里跑过一次，那一次是在单个会话内完成，没有人批准。

Claude Code 换出口

Claude Code 更难骗。研究者最终得手的文件不是客户那份，而是他们按同样思路自写的 CLAUDE.md。

文件把攻击包装成“配置项目模型网关”，要求写 .claude/settings.json，把 ANTHROPIC_BASE_URL 指向攻击者控制的域名，域名有合法证书。写进去之后，Claude Code 的每次请求都会把 OAuth 登录令牌带到这个地址。研究者拿捕获的令牌去真实 API 重放，直接以受害者身份拿到服务，全程没有执行代码。

下一步更直接。攻击者的服务器冒充模型，返回一个 Bash 工具调用，里面带着 Claude Code 自己的 dangerouslyDisableSandbox，值为 true。客户端把这条指令当成模型的决定，关掉沙箱去安装同一个恶意包。

研究者测得，配置写入约有一半概率被人批准；同一会话内跑通代码约五分之一；下一次在该目录启动时，则稳定走攻击者的通道。

两条路径的失守点不同

并排看，差别不在谁更容易被骗，而在哪一层先失守。

Codex 的支点是配置文件。它把恶意服务写进机器级配置，再用子进程和绕过标志跳出当前会话的审批与网络限制。防线应放在配置文件完整性、MCP 服务白名单和子进程参数上。

Claude Code 的支点是出站通道。它先改 API 地址，拿到登录令牌，再借模型下发的工具调用关掉沙箱。防线应放在出站域名白名单、令牌寿命与轮换上，并且不该让模型单方面决定是否关沙箱。

相同的地方是：两边都在用户提问前动手，都把一次会话里的动作变成下一次启动仍然存在的状态。只查提示词、只审代码 diff，看不到这两步。

该查的是配置，不是文采

截至 2026 年 11 月 3 日，公开渠道没有查到对应补丁。Forever 的判断是，智能体读取并服从所在目录的指令文件，是产品设计，不是漏洞；能改的是使用方式。

现在就能做的检查有三项。别把 Downloads 这类宽目录当作智能体的工作目录。打开 ~/.codex/config.toml，看有没有自己没加过的 [mcp_servers.*] 段。打开项目的 .claude/settings.json，看有没有自己没设过的 ANTHROPIC_BASE_URL、代理或其他 API 地址。

一份 13 KB 的说明文档，就能触发配置写入、依赖安装和沙箱绕过；换一份自写的 CLAUDE.md，又能把登录令牌送出去。它提醒的不是模型会不会被骗，而是智能体被允许改什么、连哪里、拿什么凭证。这三件事，才是这类攻击链真正的入口。
