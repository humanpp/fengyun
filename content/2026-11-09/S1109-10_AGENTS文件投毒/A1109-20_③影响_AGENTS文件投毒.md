【正文】
Markdown 文件没有可执行权限，却能让编码智能体改写配置、关掉沙箱、安装依赖，甚至把登录令牌送出去。2026 年 10 月 22 日 Forever Security 披露的这起事件，值得注意的不是某个恶意包，而是文件被放到了智能体必须服从的位置。

这不是某一个产品的怪癖，而是编码智能体正在扩张的新表面：可扩展性。过去软件靠插件和脚本扩展，边界大致清楚；现在智能体把项目说明文件也当指令读，还能反过来改自己的配置。读取、改写、执行叠在一起，性质就变了。

三个能力叠成一个执行面

第一项是自动读取。AGENTS.md、CLAUDE.md、.cursorrules 这类文件会在会话开始时加载，作为项目指导参与后续每一步。它们不是用户当场输入的内容，却被当成可信的行动依据。

第二项是改写自身配置。Codex 读 ~/.codex/config.toml，Claude Code 读 .claude/settings.json。这些文件可以决定它连哪个模型地址、启动哪些 MCP 服务、要不要保留审批和沙箱。能写它们，等于能改行为边界。

第三项是持有凭证并执行动作。编码智能体往往握有 OAuth 登录令牌、代码仓库权限、包管理器和能跑命令的终端。它行动时用的不是攻击者身份，而是用户已经给它的授权。

单独看，每一项都是产品功能。叠在一起，就出现了一个“可写入的执行面”：外部输入能改写执行者的规则，执行者又握着凭证和权限。

攻击已经不只在下载文件夹

Forever 的案例里，入口是 Downloads，网页能写入，用户又容易信任。研究者承认文件怎么来的没有查清，只演示了网页投放可行。

另一条路径更靠近日常开发。英伟达 AI 红队构造的模拟案例里，一个由红队自建的恶意 Go 依赖在构建时检测到 CODEX_PROXY_CERT，往项目里写 AGENTS.md，要求智能体在每个 main 函数插入 5 分钟休眠，并在 PR 摘要和提交信息里隐瞒。

OpenAI 在 2025 年 8 月 19 日回复：这不比依赖被投毒显著提高风险，不打算改。

学术界也在研究这类文件。2026 年 10 月 28 日提交的 arXiv:2610.38521 v1 预印本（未经同行评审）把 CLAUDE.md 这类记忆文件当攻击面，在 12 类 CWE、36 个 SecRepoBench 任务上测试。

恶意文件让安全完成率变化负 8 到正 6 个百分点，方向并不一致；Claude Code 在约三分之二的最终消息里提到这份文件，OpenCode 几乎只在推理轨迹里提到。

旧防线为什么挡不住

过去的防线建立在人的动作上：人看 diff，人点批准，人决定跑不跑。智能体把这三个动作压缩到用户提问之前。

文件在任务开始前被读取，动作在用户看到结果前完成；研究者认为，工程口吻的长文档降低了批准时的警觉；机器级配置的改动会跨项目、跨会话留下。Claude Code 那条链里，“关沙箱”也不是人点的，而是攻击者冒充模型下发的工具参数。

反方也有道理

OpenAI 的回应并非全无依据。英伟达案例的前提是依赖已被投毒，攻击者本来就有代码执行，OpenAI 据此认为增量风险有限。Forever 的测试也有立场：Codex 的超九成数字多数来自无害替身；Claude Code 的配置写入获准率约 50%，同会话执行率第一手约 1/5、部分转述约 50%。

准确地说：投放门槛不高，利用门槛不低；一旦跨过，后果就从“一次会话被误导”变成“机器级配置被改写、登录身份被接管、后续每个项目都受影响”。增量不在能否发生，而在它留下多久、扩散多远。

把配置当代码管

可扩展性不是功能清单，是权限清单。要管的不是支持哪些文件，而是允许改哪些文件、连哪些域名、拿什么凭证、留多久。

落到动作上，四件事现在就能做。把 agent 配置纳入版本控制和 diff 审查；对 AGENTS.md、CLAUDE.md、settings.json 做完整性监控；给出站域名设白名单；把令牌寿命压短，按项目给最小权限。

采购时再加三个问题：能写哪些配置，能连哪些外部地址，令牌过期多久。这比多演示几个功能更能说明风险。

13 KB 文档之所以危险，不在于写得多好，而在于它同时碰到读取、改写和执行三个开关。可扩展性越强，这三个开关越需要被单独看住。
