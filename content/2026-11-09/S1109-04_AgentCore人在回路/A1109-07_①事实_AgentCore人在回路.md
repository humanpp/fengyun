【正文】
2026 年 11 月 6 日，AWS 在机器学习博客上放出一个叫 sample-remote-coding-agent 的示例项目。Claude Code 不在你的笔记本上跑，而是在 Bedrock AgentCore 的远程会话里跑；任务结束，你收到的是一个 GitHub PR。

先排掉一个误会：这不是新产品发布，是一篇技术博客加一个开源示例仓库，代码明确标了非生产用途。它值得看的地方，是把“远程编码代理”拆成了能逐项检查的零件。

一个任务一台 microVM

入口有两个，Claude Code 插件 sample-rca 和带 Cognito 登录的控制台。API 侧的 Lambda 先用 Bedrock Guardrails 筛一遍提示词，写进 DynamoDB，再进 SQS 排队；筛查服务不响应，任务直接拒绝。调度器为这个任务开一个 AgentCore 会话，每个会话一台独立 microVM，CPU、内存、文件系统都隔开。

会话里的事不神秘：克隆仓库，翻 AgentCore memory 找以前任务的教训，Claude Opus 规划，Claude Sonnet 写代码，跑仓库自己的安装和测试命令，再让 Opus 复核。一个任务最多试 3 次，然后推 agent/任务号 分支，开 PR。PR 里写清测试命令、退出码和用了几次机会。

这套记忆是跨会话的：仓库的构建怪癖、没写进文档的前置条件，会被下一轮任务翻出来接着用。省事，也意味着上一轮的误判会被继承。

四道闸门

令牌是短的。Agent 不持有长期 GitHub 凭证，GitHub App 通过 AgentCore Identity 签发用户令牌，8 小时后失效，范围限于 App 已安装、且授权用户本来就能访问的仓库。

网络是收的。运行时放在私有子网，AWS 服务走 VPC 端点，出网只走一个 NAT 网关，只放 HTTPS，域名再过一道 DNS 防火墙黑名单。权限也收得紧，运行角色只能调 Anthropic 模型，并显式拒绝 AgentCore Identity 的控制面。Bedrock 侧另有零操作员访问，以及可选的零数据保留。

剩下一道是人。Agent 从不合并，测试没过就开成草稿 PR，AWS 建议把默认分支的分支保护打开。所谓人在回路，落在这一个动作上。

PR 描述里固定写三样：跑的是哪条测试命令、退出码是多少、用掉几次尝试。审核的人不必相信代理的自述，能直接对着命令和结果复核。

它没盖住的地方

部署 15 到 25 分钟，本地构建约 1.3 GB 的 ARM64 镜像；每注册一个仓库再花 8 到 12 分钟；官方列了五个区域。成本没给估算，默认的每月 200 美元 Bedrock 预算只发邮件，不封顶。

两个缺口 AWS 自己写了。Guardrails 只筛用户输入的提示词，仓库文件和命令输出里的注入看不到；DNS 防火墙是黑名单，拦不住别的 HTTPS 流量。示例也不适合不可信代码和开放式任务，因为它要跑仓库自己的命令。官方把适用面压得很窄：可信仓库、边界清楚的功能、修 bug、补测试。

这套东西的价值不在“自动写代码”，在于把交付单位从一堆改动变成了一个可审的 PR：有分支、有测试记录、有尝试次数、有合并闸门。

想照抄，先抄四件事：8 小时令牌、每任务一台沙箱、3 次上限、PR 里写测试结果。想上生产，先补两个洞：模型读到的内容谁筛，出网除了黑名单还靠什么。
