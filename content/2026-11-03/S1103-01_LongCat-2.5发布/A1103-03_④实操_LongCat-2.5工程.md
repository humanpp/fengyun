【正文】
LongCat-2.5 的技术报告里，最值得看的不是评测分数，是第四章和第六章。

前者讲怎么在显存不足 80GB 的国产卡上训 1.6 万亿参数，后者讲怎么把推理成本压下来。两章都给了具体数字和做法，可以照着抄。

限制条件先说清楚：国产加速器单卡显存不足 80GB。

1.6 万亿参数的模型，即便按 FP8 存，光权重就要 1.6TB 显存。单卡 80GB 的话，理论上至少 20 张卡才装得下权重，还没算梯度、优化器状态和激活值。实际训练中优化器状态通常比权重还大，真正的卡数需求远不止 20 张。

解法一：并行度对齐超节点，不是对齐总卡数

常规做法是先定并行策略再看硬件拓扑，美团的顺序反过来了。

报告里的做法是：FSDP 和 EP 的并行度都对齐单个超节点的卡数，CP 并行度不超过这个卡数。目的是让三类最耗带宽的通信都留在超节点内部的高带宽互联域里完成——参数聚合、专家 token 分发、KV 聚合。跨超节点的通信能少一次就少一次。

配套的还有混合词表并行，把基础词嵌入层、LM head 和 N-gram 嵌入层在 DP 和 CP 的联合并行域内切分，进一步压显存。

解法二：阈值触发的动态专家复制

MoE 架构有个老问题：专家负载不均衡。有的专家被路由到的 token 特别多，对应的卡就爆显存。

LongCat-2.5 基于 MoonEP 做了个阈值触发机制：只有当负载不均衡程度达到预设阈值时，才启用专家复制。

报告里明说了这么做的原因——避免额外通信开销超过负载均衡带来的收益。专家复制本身要花通信成本，不加判断就复制，可能越优化越慢。

解法三：把视觉编码移出计算图

LongCat-2.5 提前把图像 token 生成好，训练计算图里就不含视觉编码器了。

好处有两个。一是简化并行实现，视觉编码器的并行方式和语言模型部分不一样，混在一起很难排布。二是系统可以根据已知的图像 token 数量，在数据打包时预估各模态的负载比例，让不同并行 rank 上的模态占比接近。

配套的是双重分片 FSDP：模型参数在超节点内的 FSDP 域分片，FP32 主权重和优化器状态再通过 HSDP 副本跨 FSDP 域分片。

官方给的综合结果是：这套配置在长序列 SFT 任务上，单卡吞吐量比 DDP 基线提升 86%。

推理侧：权重和激活都压到 4bit

LongCat-2.5 用的是 W4A4：专家权重和激活同时量化到 4bit，靠国产加速器的原生 INT4 矩阵乘法单元算。

精度怎么保住的？报告说是以 FlatQuant 的可学习等价变换为基础，再针对 MoE 结构优化量化精度，在已评测的下游任务上保持和量化前相当的表现。

工程上的关键动作是在 token 复制和分发之前就完成量化，让同一份 INT4 表示贯穿专家通信和计算全过程。这样通信量也降到了四分之一。

实测数字：对比 W8A8 INT8 基线，prefill 吞吐提升 43.3%，decode 吞吐提升 42.77%，TTFT 降低 15.91%，TPOT 降低 19.72%。

长上下文 RL 的两个细节

一个是跨层预取。利用 LSA 奇数层复用前一个偶数层 top-k 索引的特点，把奇数层完整 KV 卸载到主存，显存只留小容量工作缓存。偶数层算出索引后，提前加载下一奇数层需要的 KV，和当前层后续计算重叠。结果是 TPOT 无损的情况下，Decode 阶段 KV 缓存容量接近翻倍。

另一个是容量感知调度。Router 根据 L1 加 L2 的缓存容量和请求 token 总量控制放行，优先推进完成度高的 Group，尽早凑齐训练批次释放缓存，避免多条长轨迹交替推进时反复淘汰彼此的前缀，引发大规模重算雪崩。

可以直接抄的三条

第一，并行度对齐超节点卡数，而不是对齐总卡数。跨超节点通信是主要瓶颈。

第二，视觉编码能离线预计算就离线预计算。省下的不只是算力，还有并行排布的复杂度。

第三，量化放在通信之前做，不是之后做。通信量会跟着降。

一句话判断：这份报告的价值在于它给的是一条被验证过的国产卡训练路径，而不只是参数规模。显存不够的时候，先想怎么减少跨节点通信，而不是加卡。
