【正文】
11 月 2 日，美团 LongCat 团队发布了 LongCat-2.5。总参数量 1.6 万亿，每个 token 激活约 480 亿参数，是一个面向长程智能体任务的原生多模态模型。

这个规格里有两个数字值得单独拎出来看。

第一个是 1.6 万亿。这是目前公开报道里参数规模最大的国产模型之一，比上一代 LongCat-2.0 进一步强化了原生视觉理解和智能体编程能力。

第二个是 480 亿。MoE 架构下每个 token 只激活总量的一小部分，这意味着 1.6 万亿的模型在推理时实际计算量接近一个 480 亿参数的稠密模型。这是它能在国产卡上跑起来的前提。

三项评测超过 Claude-Opus-5

美团公布的评测表共 40 项基准。LongCat-2.5 在其中几项上领先 Claude-Opus-5。

AutomationBench v1.0.6 上，LongCat-2.5 拿到 51.8 分，Claude-Opus-5 是 50.3 分。BrowseComp 上，91.9 分对 90.8 分。3DCodeBench 的文本转 3D 任务上，55.4 分对 54.3 分。LongCatClawBench FORTE 上，83.3 分对 82.6 分。

这几项的领先幅度都在 1.5 分以内。

但也有一项落后得比较明显。Terminal Bench v4.0 上，LongCat-2.5 是 38.5 分，Claude-Opus-5 是 53.9 分，差了 15.4 分。Program Bench 上，25.5 分对 37.0 分。

有两个前提要说清楚。一是 LongCat-2.5 的分数全部是美团自测；二是官方明确说明，对比模型里带星号的分数取自公开技术报告或榜单，不带星号的是美团自测，两者混排仅供参考。所以这些分差看趋势可以，看精确排名要谨慎。

视觉信号被拆成了 token

LongCat-2.5 的多模态做法和常见方案不太一样。

它没有采用外挂视觉编码器的路线，而是把不同分辨率的图像编码成离散的 token 序列，再和文本 token 一起送进同一个主干模型。具体做法是先用语义对齐编码器生成原生分辨率特征，再通过残差向量量化压成多层级词表 token。

这样做的直接好处是训练简化。视觉编码被移出了训练计算图，系统可以根据已知的图像 token 数量，提前估算各模态的负载比例，让不同并行 rank 上的数据更均衡。

代价是视觉信息的压缩损失，论文里用"缓解"这个词描述 RVQ 的作用，说明这不是无损的。

国产卡显存不到 80GB 怎么训

这是整个技术报告里最实在的部分。

国产加速器单卡显存不足 80GB，要训 1.6 万亿参数的模型，常规做法直接卡死。美团的解法是围绕超节点重新安排并行策略：FSDP 和 EP 的并行度都对齐单个超节点的卡数，CP 并行度不超过这个数，让参数聚合、专家 token 分发、KV 聚合都尽量留在超节点内的高带宽互联域里完成。

配套的还有双重分片 FSDP——模型参数在超节点内分片，FP32 主权重和优化器状态再跨超节点分片。

官方给出的结果是：这套配置在长序列 SFT 任务上，单卡吞吐量比 DDP 基线提升 86%。

推理侧用的是 W4A4 方案，专家权重和激活同时量化到 4 bit。对比 W8A8 INT8 基线，prefill 吞吐提升 43.3%，decode 吞吐提升 42.77%，首 token 延迟降低 15.91%，单 token 输出时间降低 19.72%。

价格和入口

API 按量付费，当前开放的模型是 LongCat-2.5-Preview。限时折扣价：输入每百万 tokens 2 元，命中缓存 0.04 元，输出 8 元。美元口径是输入 0.30 美元、缓存输入 0.006 美元、输出 1.20 美元。

新用户注册认证赠一千万 token，老用户加赠五百万。

网页端可以直接在 longcat.chat 体验。

没说的部分

官方没有公布上下文长度，也没有提权重是否开源。从定价页看，目前只有 API 和网页两个入口，没有权重下载。

另外也没有说明用的是哪家国产芯片，只写了"国产算力"和"国产加速器"。

一句话判断：这是一次面向智能体任务的工程导向发布，参数规模和国产算力适配是它的两个支点，但第三方复现之前，官方自测的领先幅度只能当参考。

想试的话，先用网页版跑一个自己熟悉的任务，比看评测表更能判断它适不适合你。
