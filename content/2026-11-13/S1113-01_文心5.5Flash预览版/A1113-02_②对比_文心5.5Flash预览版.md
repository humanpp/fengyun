【正文】
百度给文心 5.5 Flash Preview 配了一张 20 项的跑分表，7 个模型同表。全表最高的 3 项是它的：AutomationBench 61.9、SpreadsheetBench V2 36.4、MCP-Atlas 84.6。

三项里两项在办公与表格，一项在工具调用。这个分布，比总分更能说明它是给什么场景做的。

先看这张表怎么读。本模型那一列无星号，是百度自测；对手列常写成"官方值 / 带星号值"，前者取自对方官方报告或公开榜单，后者是百度用同一套脚手架复跑的。

脚手架本身也会带偏。Terminal-Bench 4.0 一行另有脚注：GPT-6.1 Sol 的 56.1 引自 Artificial Analysis 榜，其余模型用 Claude Code 2.1.246 评测。同一张表里，评测环境并不完全统一。

所有数字来自同一张表，可以横向比，不能拿去和其他榜单拼。

终端任务：同档领先，头部还远

Terminal-Bench 4.0 它拿 46.5，高于 Hy4 的 44.4、DeepSeek-V4.1-Flash 的 42.3、GLM-5.3 的 41.8，低于 GPT-6.1 Sol 的 56.1 和 Claude Opus 5.5 的 66.4。

同一族的终端科研任务 Terminal-Bench-Science 0.1 只有 21.0，Claude Opus 5.5 是 63.3，GPT-6.1 Sol 是 57.0。同档对手里它仍是高位，Hy4 是 19.8，但这一项的天花板明显在另一侧。

程序合成差得更直白。ProgramBench 29.5 对 Claude Opus 5.5 的 65.0；DeepSWE 71.2，低于 DeepSeek-V4.1-Flash 的 77.0 和 GPT-6.1 Sol 的 75.2。

办公场景是它的地盘

AutomationBench 61.9 全表最高，比 DeepSeek-V4.1-Flash 的 60.5、Claude Opus 5.5 的 58.0 都高。SpreadsheetBench V2 36.4 也是全表最高，Claude Opus 5.5 是 35.1。

不是每项都赢。OfficeQA Pro V2 它是 67.9，GPT-6.1 Sol 是 70.0；浏览器操作 BrowsesComp 是 87.4，Hy4 到 91.8；表格关系型任务 DRACO 是 84.9，Hy4 到 90.7。这三处差距不算大，但对"能不能直接替掉手上那套方案"这件事，往往是决定性的。

窗口大不等于检索准

上下文给了 100 万 token。可长上下文检索项 AA-LCR v1.1 只有 79.0，Claude Opus 5.5 是 84.7，Hy4 是 80.0。

这个反差值得记住：窗口是配置允许的上限，检索准确率是另一回事。把整本手册塞进去之前，先想清楚它能不能在里面找对那一页。

通用知识是短板

HLE 它只报了纯文本子集，46.4；Claude Opus 5.5 是 61.4。AA-Omniscience 25.2，对 Claude Opus 5.5 的 62.0、GPT-6.1 Sol 的 52.8。

这两项测的是知识面与冷知识，不是中文能力，也不是推理链路。短板在这一格，意味着把它当"什么都知道"的问答入口会失望。

有个反直觉的地方

官方宣传里最响的是编程。可编程这一族里，它真正领跑同档的只有终端任务的 46.5，越往整库改动、科研级终端操作走，差距越大。

反倒是不太被提起的表格与工具调度，成了全表最高的两项。这个错位值得记住：宣传词与强项不在同一处。

怎么选

做中文办公文档、表格处理、浏览器自动化、多工具编排，这一档可以用。代价是每百万 token 输入忙时 2 元、输出忙时 8 元，闲时减半。

做长程终端工程、整仓代码改造、科研级终端任务，别把希望放在预览版上。AA-Omniscience 那一格说明，通用知识问答也不是它的强项。

还有一条：它的上下文上限是 100 万 token，但 AA-LCR 这一项排在对手之后。要拿它做超长文档处理，最好先用自己的一份长材料单独试一遍。

最后一句判断：官方说"有竞争力"没说错，但要加定语，有竞争力的是同尺寸开源档和办公类任务，不是全表。选型时按任务拆开测，别用一张总分表定生死。
