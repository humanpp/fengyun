【正文】
我没有在本机跑这一遍，先把能核对的核对完了：官方那 7 组提示词写了什么、演示里 Agent 走了哪些步、安全须知说了哪些不能指望。下面是一条按官方材料推出来的上手路线，和五个能提前避开的坑。

先装对，再试用

装的是代码，跟每次聊天的账单是两码事。终端里跑 npx @deepseek-ai/dsh web，本地默认开在 127.0.0.1:3080，桌面端也有安装包。要先装 Node.js。

装好之后还有两步容易漏：在设置里填模型供应商的 API Key，给一个工作目录。第 1 个坑就在这儿。模型不接上，Agent 不会写一行代码，页面只会安静地转圈。

跑官方样例，挑最轻的那个

七组官方提示词里，四组要碰文件、要调库；两组改应用外观；一组加侧边栏。

第一遍跑，选五套界面主题那组。它不写文件、不调外部接口，跑坏了删插件重来就行。跑通一次，就知道这套流程在自己机器上有多快，再去碰番茄钟那种要挂 overlay 的。

第 2 个坑：5 分 24 秒不是标准

产品页那个计时器一直在跳，最后停在 5 分 24 秒。官方在同一页的脚注里补了一句，部分演示插件经过多轮对话打磨，一条提示词不一定复现视频里的结果。

第一次没跑出来很正常，接着对话调整就行。真跑不顺就把需求拆细：先说"要一个悬浮窗"，再说"要两个按钮"，最后说"要倒计时声音"。

需求写得越像验收标准，它返工越少

演示里 Agent 挑显示位置那一步值得学。它没猜，先去查应用里哪些地方能挂悬浮窗，再选了铺满窗口的一层。

提示词里可以照这个思路补一句：请先看应用已有的扩展点，用现成的，不要自己造。

第 3 个坑：代码量比想象的大

番茄钟那次，client.js 净增 638 行。这不是缺陷，有这么多行才撑得起悬浮窗、按钮和倒计时。但它意味着你不太可能扫一眼就判断它干了什么。

安全须知写着，运行前要审阅插件、配置和要执行的命令。这句话放在 638 行面前，是个很实在的负担。

第 4 个坑：它验证的是"活着"，不是"安全"

演示最后一步是看插件有没有在线。这个检查说明它装成功了，不说明它只做了番茄钟该做的事。

我的做法是把它放在容器或一次性虚拟机里跑，主工作目录别跟着进去。插件装在宿主进程里，权限跟宿主持平。

第 5 个坑：版本在动

Harness 是开发者预览版，官方仓库用大写字母写着：会出现破坏兼容性的变更。每次升级后，先用最轻的提示词确认链路还在，再去改真在用的东西。

想延伸到常驻，多走一步

只想要一个插件的话，上面这些够用了。

想要一个住下来的进程，比如 Super-agent 那种监听仓库、收到要求就开 PR 的，还得多做三件事：准备一个独立的 GitHub 账号，别用你自己的；配一个独立的系统账户，因为官方明说两个预设都以全权限运行、能读到操作者的主目录；把个人账号的命令行工具列进禁用清单，防它顺手用了你的身份。

通读下来的意外

7 组提示词里，我印象最深的是视频剪辑工作台那一组。需求写得像验收清单：深色主题、大预览、时间线、支持多个视频上传、能导出、能用对话剪辑。

写需求时照着这个句式拆，比写一段抒情描述有用得多。

不适合谁

不想读代码、也不想做隔离的人，先别装。它的便利和暴露面本来就是一件事。

只想要现成工具的人，等社区有人做出可一键安装的包再回来。你只需要决定装不装。

我的判断

Creator Mode 把"造一个工具"的成本降到了一句话，没把"确认这个工具安全"的成本降下来。先跑最轻的样例，再碰文件，再谈常驻，这个顺序能少吃一半的亏。

哪一篇都没替你验证

三篇说下来，有一条同样的底：功能写在官方页面上，风险写在官方文档里。装不装、装在哪儿、给多大权限，文档给的是建议，决定得自己做。
