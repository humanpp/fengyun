【备选标题】
1. 逐项对比：Kimi 21 赢 20 输，差距在哪
2. Kimi 强在检索弱在长链条：41 项逐项对照
3. Kimi 与 Opus 5.5 逐项比，输的那几项差更多

【正文】
月之暗面给 Kimi K3.1 Pro 配了一张很长的评测表，同一张表里有 Claude Opus 5.5、GPT-6 Astra、Claude Fable 5.1、DeepSeek-V4.1-Flash-1017 和 GLM-5.3。

我按官方表格逐项对了一遍。只算 Kimi 与 Claude Opus 5.5 双方都有分数的项目，共 41 项，21 赢 20 输。

这个数字看着像势均力敌，但把每一格的差距摆出来，情况就不一样了。

赢的地方，差距都不大

赢的项多集中在检索、文档、结构化处理和办公类任务。

BrowseComp 上，Kimi 是 92.1，Opus 5.5 是 90.8。带工具的 HLE 上，70.0 对 67.7。OfficeQA Pro v2 上，64.4 对 62.2。MMMU-Pro 带 python 上，90.0 对 89.8。Automation Bench-AA 上，73.3 对 69.5。

这几项的共同点是：给定材料，找答案、算数字、出结论。按百分制计分的项目里，差距普遍在 1 到 4 分之间，最大的一项是 SWE Marathon，51.7 对 46.3，也只差 5.4 分。

输的地方，差距被放大

输的项差距大得多。

Program Bench 上，Kimi 是 31.5，Opus 5.5 是 65.0，差 33.5 分。Terminal-Bench-Science 上，38.1 对 63.3，差 25.2 分。HLE-Diamond 上，39.4 对 60.9，差 21.5 分。

还有几项方向一致但幅度小些：BenchCAD 带工具 92.7 对 96.2，OSWorld V2.1 79.6 对 81.8，APEX-Agents 67.2 对 73.5。

把输的这几项排在一起，规律很清楚：需要连续几十步操作、中途还要自己纠错的任务，Kimi 落后；给定材料一次性给出结论的任务，Kimi 领先。

Program Bench 考的是完整程序构建，Terminal-Bench-Science 考的是科学计算场景下的终端操作，HLE-Diamond 考的是最难的推理题，三类都落在前一类。

另有两项用的是 Elo 分，差距看起来更刺眼。

AA-Briefcase v1.1 上，Kimi 是 1678，Opus 5.5 是 1803，差 125 分。GDPval-AA v2.1 上，1846 对 1866，差 20 分。这两项考的都是交付物质量，前者偏商业文档，后者偏真实职业任务。

反过来，官方自建的 DECK-Arena 上 Kimi 是 1456，Opus 5.5 是 1253，领先 203 分。这是自建基准，读数要打折。

换成 GPT-6 Astra 做对照

对 Astra，Kimi 在检索和办公类上同样占优：BrowseComp 92.1 对 91.5，OfficeQA Pro v2 64.4 对 54.4，Automation Bench-AA 73.3 对 68.5，带工具的 HLE 70.0 对 57.2。

但推理类的差距反过来被放大：HLE-Diamond 39.4 对 65.8，Terminal-Bench-Science 38.1 对 68.1，PerceptionBench 68.3 对 77.6，Design Bench 的 Elo 是 957 对 1076。

这一组同样 41 项可比，22 赢 18 输 1 平。也就是说，对 Opus 5.5 是胜负各半但输得更狠，对 Astra 是检索类明显占优、推理类明显吃亏。

在开源权重这一档里，领先幅度更大

同一张表里还有两个开源权重模型：DeepSeek-V4.1-Flash-1017 和 GLM-5.3。

对 DeepSeek，Kimi 在多数项目上领先且幅度不小：Terminal-Bench 4.0 是 65.7 对 42.3，OfficeQA Pro v2 是 64.4 对 40.4，HLE-Full 带工具 70.0 对 58.8，OSWorld V2.1 79.6 对 69.3。DeepSeek 领先的项目是 DeepSWE v1.1，77.0 对 75.5，以及 xdev-bench-hard 的 85.7 对 81.0。

对 GLM-5.3，差距更大：Terminal-Bench 4.0 65.7 对 41.8，Program Bench 31.5 对 19.0，OfficeQA Pro v2 64.4 对 31.1。

三项开源模型里，Kimi 的位置是明显领先，但它领先的方式和面对闭源时一样：检索与办公拉开差距，长链条工程和推理题上优势有限。

跨表比分数，有三件事必须说清

第一，Kimi 自己的分数全部在 max 推理档位下自测。

第二，对手分数取自各家博客或官方榜单的最大值，其中多家标注了 with fallback。测试环境不完全一致，只能读量级和方向，不能读精确排名。

第三，幻觉类基准是越低越好。官方内部基准 Kimi Hallu Bench Hard 上，Kimi 是 8.3，Opus 5.5 是 15.0，GPT-6 Astra 是 5.5。

一句话判断：Kimi K3.1 Pro 已经把检索、文档、办公这类任务做到第一梯队，价格在国产模型里也偏低；但仓库级重构、科学场景下的长链条终端操作、以及最难的推理题，它和顶尖闭源模型之间还有一段明确的距离。

选型建议：如果你的活是读文档、查资料、做表格、跑中等长度的自动化流程，现在就可以试；如果要它独立完成一个跨文件的大改造，或者啃奥林匹克级难题，先别把主力切过来。
