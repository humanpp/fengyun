【正文】
2026 年 11 月 4 日的 Hy4 发布稿里，被讨论最多的是视觉理解，但对企业来说真正改变成本结构的是另一条：首次支持电脑操作。

意思是模型能看屏幕、动鼠标键盘，也能敲命令行，两种入口可以混着用。

先说这个变化传导到谁身上

第一类是内部系统的运维和业务部门。

很多公司的 ERP、OA、报销、工单系统是十年前上线的，没有 API，或者 API 只开放了一部分。想接自动化，过去只有两条路：改造系统，或者雇人手工点。

Hy4 这类能力提供了第三条路：让 Agent 像人一样操作界面，不改动现有系统。

腾讯在发布稿里点名了两类软件：Blender 和 CAD。前者是三维建模，后者是工程制图，都属于过去必须以人操作的软件。官方说针对这些专业软件和跨应用长程任务做过专项训练。

第二类是游戏和前端的开发者。

官方称 Hy4 已深度适配 UE、Unity、Godot 三个引擎，并开始扩展至多人联机游戏开发。游戏侧的可量化数据是：GameDev 评测比 preview 提升 19.1%，GameLogic 提升 9.8%。这两个数字的测试集条目数官方未公布。

第三类是那些想用 AI 但数据不开放的岗位。

财务、投研、法务的很多工作发生在本地软件和内部系统里，图片和截图是最常见的输入形式。视觉理解补上了这一环。官方举的例子挺具体：28 亿像素的航拍图里找出约 2 米的屋顶构件。

为什么说训练环境是这件事的关键

让模型学操作软件，最贵的不是算力，是环境。

你不可能让一个模型在真实企业的 ERP 上试错，点错一次就是一笔脏数据。

混元的做法是与腾讯云 Agent Runtime 团队搭一套沙箱，在里面部署数百款应用软件，让模型反复执行任务、验证结果。Agent Runtime 也向企业和开发者开放。

这条信息比分数重要。它说明电脑操作能力不是靠看视频学会的，是靠反复在可回滚的环境里练出来的。也说明这类能力的上限取决于能搭出多逼真的沙箱，而不是模型本身有多大。

企业侧还有人补上了另一半

模型能操作是一回事，能稳定地长跑是另一回事。

腾讯云 ADP 给 Hy4 配了三层能力。第一层是自然语言搭 Agent，描述需求就能生成可发布的工作流，Claw 模式支持零代码。

第二层叫 Agent Harness，解决的是长程任务最怕的问题：跑到第 15 步断了怎么办。这套机制支持断点续跑、按需启停和全链路可观测，trace 可以回放每一步的输入输出。

第三层是企业级 Service Agent，把构建、评测、分发、治理、管控连在一起，配套权限与安全策略。

三层里，第二层才是把「能跑」变成「能上生产」的那道坎。

也得说个反方

第一，屏幕操作这条路本身有天花板。图形界面的容错率远低于 API，一次弹窗、一次坐标偏移就可能走错。靠谱的做法仍然是把有 API 的部分用 API，把没有的部分才交给 GUI，而不是反过来。

第二，幻觉率从 15.76% 降到 5.45% 是官方自建测试的结果，方法未公开。5.45% 放在长跑任务里意味着什么，取决于任务有多长：跑 20 步、每步都有 5.45% 的出错概率，累计下来的失败率不低。

第三，官方在发布稿中承认，Hy4 与顶尖闭源模型在前沿数学、长程开发等高难度测试集上仍有较大差距。

我的判断

企业上 Agent 的真正瓶颈，过去两年一直不在模型智商，而在够得着。

数据在 PDF 里、在截图里、在没有接口的老系统里，模型再聪明也进不去。这一代补的正好是这段：视觉让你把截图变成输入，电脑操作让你把界面变成接口。

但这不是终点。够得着之后，接下来的瓶颈会回到可靠性和成本上，而这两件事恰好都需要权重和系统卡片才能验证。

一句话行动建议：如果你的团队正卡在某个没有 API 的老系统上，现在值得做一次小范围验证，趁 2026 年 12 月 31 日腾讯云 TokenHub 按量调用五折；但别急着大规模切换，等系统卡片和权重出来再说。
