【正文】
2026 年 11 月 4 日之后，腾讯混元在同一个价位上同时挂着两代旗舰：8 月 28 日的 Hy4 preview 和刚上线的 Hy4 正式版。

把两代并排放，会发现一件不太常见的事：新的那个能力更强，但可自行部署的部分更少。

先比参数：这次官方没给

Hy4 preview 的规格是公开的：总参数 770B，每 token 激活 49B，78 层，第一层是标准 FFN，其余 77 层是 MoE，每层 256 个路由专家加 1 个共享专家，每 token 激活 top-8，上下文 1M tokens。

注意力侧用的是 Gated DeepSeek Sparse Attention 加 IndexCache，残差侧是 iHC，即 identity Hyper-Connections，共 4 条残差流。这套说明写在 GitHub 仓库的 README 里。

正式版呢？官方发布稿里没有参数、没有层数、没有上下文重述，只说显著扩展了预训练和后训练规模。

所以严格讲，说 Hy4 正式版「还是 770B」是一种推定，不是一个被官方确认过的事实。写文章时这一点必须交代。

再比能力：两项是从零到一

Hy4 preview 只处理文本。正式版第一次能看图，也第一次能操作电脑，命令行和图形界面可以混着用。

这是两代之间最根本的差别，不属于「强一点」的范畴，而属于「原来没有」。如果你之前因为 preview 读不懂截图而放弃某个方案，这条就是重做一遍的理由。

游戏侧有可量化的对照。官方称 Hy4 在 GameDev 评测中比 preview 提升 19.1%，GameLogic 提升 9.8%。注意，测试集条目数官方没有公布，这两个百分比只能当方向看，不能当绝对水平用。

然后比可靠性

幻觉率从 15.76% 降到 5.45%，猜测导致的错误率从 23.1% 降到 5.6%。

这也是官方自建测试，方法未公开。

第三处对比：开放度，方向和能力反着走

这是两代差异里最不该被忽略的一段。

preview 发布当天就把权重放了出来，Hugging Face、ModelScope、GitCode、CNB 四个渠道都有，许可证是 Apache 2.0，还附了 vLLM 和 SGLang 的部署说明、推荐采样参数 temperature 0.9、top_p 1.0。

正式版目前没有权重仓库，没有许可证，没有部署配方，也没有系统卡片。官方只说「近期开源模型权重、发布模型系统卡片」。

还有一份材料也少了。preview 当年发了一份 benchmark 附录，里面有八行分数：Terminal-Bench 2.1 是 85.4，DeepSWE 是 64.3，SWE-bench Pro 是 65.7，SWE-bench Multilingual 是 82.9，Toolathlon-Verified 是 74.1，OneMillionBench with tools 是 65.4，SWE Atlas Refactoring 是 53.3，APEX-Agents 是 37.1。

正式版没有更新其中任何一行。也就是说，截至 2026 年 11 月 4 日，没有任何公开数据能说明正式版在软件工程任务上比 preview 强。

一处不寻常的坦白

安全评估里有一个全部发布材料中最不好看的数字：Hy-BioExperimentBench 得分 30.4，满分 100。

官方在发布稿里承认，Hy4 与顶尖闭源模型仍有较大差距，尤其在前沿数学、长程开发、模型迭代、视觉问答的高难度测试集上。

这两条放在发布稿里，其实是在给官方那句「跻身开源模型前列」划边界。

两代各适合谁

要本地跑、要微调、要把权重捏在自己手里，选 preview。Apache 2.0 加上现成的部署命令，这是 2026 年 11 月 4 日当天能拿到的路线。注意 770B 的体量即使量化后也是多机集群的活，不是工作站能扛的。

要读图、要看屏幕操作软件、要跑长程任务，只能选正式版。preview 做不到这些，不是贵一点便宜一点的问题，是这件事它干不了。

只想通过 API 跑文本任务，两代同价，都可用。但正式版是否真的更好，目前只能靠自测，官方没有给出可对照的公开数据。

一句话判断：这不是一次常规迭代，是一次「把能力往前推、把开放度往后收」的产品决策。

建议你按任务类型选，而不是按版本号选。要动手的话，趁 2026 年 12 月 31 日之前腾讯云 TokenHub 按量调用五折，把自己最常跑的任务在两代上各测一遍，记下 token 消耗，这个数字比任何榜单都准。
